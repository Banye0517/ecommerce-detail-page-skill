# 电商详情页策划 Skill

基于设计师"般叶"8年零食电商设计经验，并已扩展至母婴食品（乳制品 / 婴幼儿辅食 / 营养品）、洗护、日用品、小家电等 6 类品类画像。**这是一个前期策划工具，不是自动出图工具。** 核心价值：帮你想清楚每一屏写什么文案、放什么画面、为什么这样设计。

## 核心定位

帮你完成详情页设计中最难的"想清楚"阶段：
- 竞品在做什么？他们的文案和画面策略是什么？
- 我们的消费者在乎什么？
- 每一屏应该传达什么信息？用什么文案？配什么画面？
- **为什么这样设计？**（每屏必须给出设计理由）

最终交付给你的是一份可直接拿去执行的**策划文档**，不是成品页。

## 核心能力

1. **竞品分析** — 搜索同类产品详情页，拆解文案策略和画面打法
2. **消费者分析** — 谁买、为什么买、担心什么
3. **FBE 卖点转换** — Feature → Benefit → Emotion → 视觉方向
4. **逐屏策划** — 每屏输出：文案 + 画面描述 + 设计理由
5. **视觉方向** — 整体配色、构图、字体建议
6. **HTML 预览（可选）** — 需要可视化时生成

## 工作流程

接到详情页策划需求时，严格按以下顺序执行：

### 阶段 0：识别品类并加载专属画像（必须先做）

不同品类的消费者、视觉规则、竞品打法差异很大，先锁定品类再策划。

1. 根据产品名和卖点判断品类（如"洗发水"→ 洗护用品，"牛奶/酸奶"→ 乳制品，"婴幼儿米粉/果泥"→ 婴幼儿辅食，"DHA/钙铁锌/益生菌"→ 营养品，"猪肉脯"→ 零食/肉脯类，"婴儿浴桶"→ 日用品，"行车记录仪"→ 小家电）
2. 查 `references/categories/_index.md`，找到匹配的品类画像文件；**易混淆品类先看该文件的「路由判据」表**（如溶豆/米饼要看包装执行标准号才能定归属）
3. **加载该品类的专属画像**（消费者画像、视觉规则、竞品特征、FBE 示例、逐屏差异、广告法专节），后续阶段 1-5 必须结合该画像执行
4. 若品类未匹配（如全新品类），加载 `references/consumer-psychology.md` 通用框架，并在输出开头提示用户："当前品类暂无专属画像，已用通用框架策划，可补充 `references/categories/<品类>.md` 提升精度"

**特别提醒（营养品）**：营养品类产品**必须先确认法律身份**——保健食品（有蓝帽子 + 注册号/备案号）、普通食品（凝胶糖果/固体饮料等，无蓝帽子）、或辅食营养补充品（GB 22570-2014）。身份决定文案能写到什么程度，未确认身份不得开始撰写文案。详见 `references/categories/nutrition-supplement.md` 第一节。

**注意**：品类画像只增强分析精度，不替代通用方法论（FBE、6 屏结构、视觉规则仍然适用）。洗护用品等跨品类品类，其说服逻辑与零食不同，必须遵循画像中标注的「逐屏策略差异」。

### 阶段 1：消费者分析

加载 `references/consumer-psychology.md`（通用框架），并结合阶段 0 加载的品类画像，按框架分析：

1. **谁买单？谁使用？谁影响决策？**
2. **购买原因 TOP3** 是什么？
3. **真正想获得什么？**（深层情感，不是表面需求）
4. **担心什么？**（糖、添加剂、品质疑虑）
5. **竞品普遍没满足什么？**（找出差异化机会）

### 阶段 2：竞品分析（必须先做，不可跳过）

这一阶段的目标是搞清楚"别人怎么做的"，避免拍脑袋策划。**竞品选择必须有真实数据支撑，不能随便找几个看起来像的。**

#### 选品标准

必须选取 **3-5 个**同品类中数据表现好的真实竞品。筛选标准：

| 标准 | 说明 | 获取方式 |
|------|------|---------|
| **销量好** | 月销量排名靠前、评价数量多 | 搜索时关注"按销量排序"、好评数 |
| **页面留存率高** | 详情页内容完整、结构清晰、一看就是用心做的 | 访问竞品链接后判断 |
| **主图点击率高** | 主图有创意、差异化明显、不是千篇一律的模板 | 对比搜索结果中多个产品主图 |

**选品方法（分两轮搜索，链接获取为最高优先级）**：

**第一轮：确定竞品名单**

使用 WebSearch 搜索"[品类名] 淘宝 销量排行 热销"，从排行榜/销量榜单中获取高销量竞品的品牌名和产品名。这轮只记名字和数据，不记链接。排行榜类网站（如 am10.com、xing73.com）只用于获取品牌名和销量数据——它们的链接不是商品详情页直链，不可直接使用。

**第二轮：逐一获取商品详情页直链（核心步骤，不可跳过）**

对第一轮确定的每个竞品，单独搜索"[品牌名] [产品名] 天猫"或"[品牌名] [产品名] item.jd.com"，获取可直接访问的商品详情页链接。

链接有效性硬性要求：
- ⭐ 必须是商品详情页直链：detail.tmall.com / item.jd.com / item.taobao.com
- ❌ 禁止使用第三方排行榜/导购/聚合网站链接（am10.com、smzdm.com、chjia.com、uland.taobao.com 等）
- ❌ 禁止用搜索关键词代替链接（如"搜索XX即可找到"）
- ❌ 禁止使用明显是内容营销而非商品页的链接（如 bk.taobao.com 知识库页面）
- 如果反复搜索仍无法获取商品直链，标注为"链接待补充"并说明搜索了哪些关键词，不要用无效链接凑数

**链接获取优先于竞品数量**——宁可只有 3 个带真实直链的竞品，不要 5 个带假链接的。少于 3 个可访问直链说明搜索不够充分，必须继续补充。

#### 自动抓取方法（全品类通用 SOP）

完整 SOP 见 `references/competitor-research.md`，对**所有品类通用**（零食/洗护/日用品/小家电/纸巾/……）。要点：

- **主动搜、必须带真实直链**：接到任何品类需求，阶段 2 都先去搜 3-5 个真实竞品详情页（`item.jd.com` / `detail.tmall.com` / `item.taobao.com`）。
- **WebSearch 优先**：用 `品牌+品类+京东/天猫 商品` 搜，优先拿直链。
- **WebSearch/WebFetch 故障时用子代理兜底**：本会话 WebSearch/WebFetch 偶发"参数未传入"类故障——此时**不要卡住、也不要编造链接**，改派一个 general-purpose 子代理独立检索（子代理路径通常可用），prompt 写清要真实直链、收集字段、禁止编造、工具报错就回"网络工具不可用"。
- 拿不到的标"链接待补充"，绝不编 URL。

**禁止行为**：
- 不能编造竞品信息
- 不能使用无法验证的"据说""好像"
- 不能只搜到 1-2 个就满足
- **不能用无效链接充数——打不开的链接比没有链接更差**

#### 分析框架

对每个竞品逐一拆解，并附上**真实产品链接**：

| 维度 | 分析内容 |
|------|---------|
| **基本信息** | 品牌名、产品名、价格区间 |
| **数据表现** | 月销量、好评率、累计评价数（从搜索结果或详情页提取） |
| **产品定位** | 他们主打什么？健康？好吃？性价比？ |
| **首屏策略** | 首屏写了什么文案？放了什么画面？主图有什么特点？ |
| **核心卖点表达** | 他们把卖点翻译成了什么消费者语言？ |
| **视觉风格** | 什么配色？什么摄影风格？什么调性？ |
| **结构安排** | 各屏怎么排的？重点放在哪？ |
| **做得好的地方** | 哪里值得学习？（如果数据好，说明这些做法经过了市场验证） |
| **做得不好的地方** | 哪里可以改进？竞品没有做到什么？ |
| **产品链接** | 真实商品详情页直链（detail.tmall.com / item.jd.com），必须可点击访问。不是排行榜链接、不是搜索关键词 |

#### 输出要求

- 至少分析 3 个竞品，附上真实可点击的商品详情页直链（detail.tmall.com / item.jd.com 格式）
- 链接无法获取的竞品必须明确标注"链接待补充"，并说明原因
- 总结"竞品普遍做法"和"我们的差异化机会"
- 竞品的数据表现要量化（如"月销 1 万+""好评率 99%"），用数据支撑分析的可靠性

### 阶段 3：FBE 卖点转换

加载 `references/fbe-sellpoint-model.md`，对用户的每个产品卖点执行 FBE 转换：

```
Feature（产品有什么）
    ↓
Consumer Truth（消费者真正在乎什么？结合阶段1的消费者分析）
    ↓
Benefit（翻译成消费者能听懂的话）
    ↓
Emotion（让人产生什么感觉？）
    ↓
Visual Direction（画面方向：拍什么、怎么拍）
```

要求：
- 每个卖点必须转换成消费者语言，禁止"高级、大气、品质"等空泛词
- 情绪价值必须落到具体的画面方向
- 转换结果应和竞品对比，确保有差异化

### 阶段 4：逐屏策划（核心输出）

加载 `references/detail-page-structure.md`，**按阶段 0 加载的品类画像的逐屏框架**逐屏输出。

**屏数不写死**（这是硬规则）：零食等通用品类可参考下方 6 屏骨架；小家电、乳制品、婴幼儿辅食、营养品等品类已在各自画像中定义**弹性框架**（屏数 = 本品卖点数 + 铺垫屏），必须按画像执行，禁止硬套 6 屏或任何固定屏数。

**每屏输出格式**：

```
### 第X屏：[屏名称]

**核心目标**：（这一屏要达成什么转化目的？）

**文案**：
- 主文案：XXX（≤10字，精炼简洁，一句说清本屏核心信息）
- 副文案：XXX（≤12字，补充说明或强化主文案）
- 辅助文案/标签：XXX（字数不限，用于数据、规格、场景标签等辅助信息）

**画面描述**：
- 拍什么：（具体画面内容）
- 怎么拍：（构图、光线、氛围）
- AI生成Prompt建议：（如果需要AI生成画面，给中英文Prompt）

**设计理由**：
（为什么这样写/这样拍？结合消费者心理和转化逻辑解释）
```

**文案字数铁律**：
- 每屏必须有且只有一个核心信息，由主文案承载
- **主文案 ≤ 10 字** — 消费者3秒扫读只记住一句话，长了等于没写
- **副文案 ≤ 12 字** — 补充说明也不能啰嗦
- 辅助文案/标签字数不限，但不要堆砌
- 如果文案超过字数限制，说明信息提炼不够——删到极限

**首屏铁律**：
- 必须出现：产品主体、核心卖点（一句话）、使用场景
- 绝对不能出现：大量参数、空泛口号、只有产品没有场景

**6屏结构参考（仅"通用框架"品类的骨架，其他品类以各自画像的弹性框架为准）**：

| 屏序 | 核心目标 | 内容方向 |
|------|---------|---------|
| 首屏 | 3秒吸引停留 | 产品大图 + 核心卖点 + 使用场景 + 一句说清价值 |
| 第二屏 | 建立购买理由 | 消费者痛点 + 产品如何解决 + 竞品对比 |
| 第三屏 | 建立信任（原料） | 原料/成分展示 + 溯源 + 配料表可视化 |
| 第四屏 | 强化欲望 | 工艺/口感/体验 + 让人想吃 |
| 第五屏 | 消除顾虑 | 检测报告 / 配料表与糖含量（不用"无添加"类用语，见 `fbe-sellpoint-model.md` 新规一节）/ 品质保证 |
| 第六屏 | 推动下单 | 使用场景 + 规格套餐 + 行动号召 |

结构可根据产品特点灵活调整屏序和数量，但必须遵循"先情感后理性、先打动再说服"的逻辑。

### 阶段 5：整体视觉方向

加载 `references/visual-design-rules.md`，给出整体视觉方向建议：

- **配色方案**：主色 + 辅色 + 底色（为什么选这个色？）
- **摄影/画面风格**：什么光源、什么构图、什么氛围
- **字体建议**：标题字体 + 正文字体
- **整体调性**：3个关键词概括
- **避免的���向**：什么风格不能做？

每一项都附带商业理由。

### 阶段 6：HTML 预览（可选）

**仅在用户明确要求预览时执行。**

从 `assets/html-templates/` 中选择模板，按文案和视觉方向填入内容生成可视化框架。生成后截图展示。

注意：HTML 中的内容来自阶段 4 的策划文档，不要凭空编造。

## 输出格式

完成后给用户的最终交付物是一份结构清晰的策划文档，按以下顺序：

1. **消费者画像**（谁买、为什么买、担心什么）
2. **竞品分析**（附真实产品链接 + 数据表现 + 逐维拆解）← 链接必须可访问
3. **卖点转换表**（FBE全链路）
4. **逐屏策划**（每屏：文案 + 画面 + 设计理由）← 这是核心
5. **整体视觉方向**（配色/构图/字体/调性）
6. **HTML预览**（如用户需要）

## AI 行为准则

加载 `references/ai-design-rules.md`，严格遵守：

**三大禁忌**：
- 不说空泛词（高级/大气/简约）
- 不只讲产品不讲人
- 不只求好看不重转化

**四项铁律**：
- 先分析购买者
- 卖点转人话
- 视觉建议配商业理由
- 按转化逻辑排页面

**新增一条**：
- **每屏必须输出设计理由** — 不只告诉用户"怎么做"，还要告诉他"为什么这样做"。这样用户才能判断你的策划对不对，也能学到东西。
- **主文案不超过10个字，副文案不超过12个字** — 消费者3秒扫读只记住一句话。文案是删出来的，不是写出来的。
